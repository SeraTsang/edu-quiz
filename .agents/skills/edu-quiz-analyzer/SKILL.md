# 教综解析 → 模糊/易错辨析题（edu-quiz）

## 使用时机与任务边界

当用户粘贴一道或多道教综试题的**答案解析**，要求“整理模糊点 / 易错点 / 做成辨析题 / 导入辨析题库”时使用。**无需原题题干**。支持答案解析、教材段落、笔记，也支持 OCR 文本（先纠正明显识别错误，不能凭猜测补充缺字）。

不用于原题逐字还原；不把原选择题的 A/B/C/D 字母映射成辨析题的真假。不因原解析写“正确答案为 C”就把新辨析题设为正确。用户若要求保持原解析措辞，应尊重其限制。

**输入**：用户粘贴的原始文字，默认不追问题干。可选参数：

- `章节：教育学 · 第一章`（仅 JSON 章节包需要；缺省时清楚标为 `教综 · 待分类`，不冒充真实章节）
- `题数：N`（缺省每个独立核心考点生成 2–3 道；整次通常 3–8 道，不为凑数重复出题）
- `难度：基础/易错/综合`（默认易错）
- `格式：粘贴`（默认）或 `格式：JSON章节包` 或 `格式：只看分析`
- `补充验证：是/否`（默认否，仅在可联网且用户明确要求时查证争议、扩展或法规时效性；标明新增来源）

可以在当前对话中直接说：`用 edu-quiz-analyzer 处理下面解析：……`。

## 核心工作流程

### 1. 从解析中解构考点

- 去掉“本题考查……”“故选 C”等针对原选择题的无关套话；**保留条件、限定词和逻辑关系**。
- 把每个解析拆成：**核心命题**、**概念边界**、**相邻易混概念**、**典型误区**、**适用情境**。若多段重复同一考点，合并去重。
- 识别可考方式：概念偷换、划分依据混淆、主体/客体颠倒、部分代整体、必要/充分混淆、因果倒置、限定条件遗漏、例子误判、绝对化表述。
- 遇到来源中模糊或自相矛盾的断言，说明“材料不足 / 教材表述可能不同”，不强行编写确定真假题。不要假设原题的完整题干或选项。

### 2. 设计可判定的辨析题

- 每个有价值的考点优先组合：**定义/边界题 + 易混误判题**；必要时加**情境迁移题**。答案应在正确、错误之间自然分布，不必强求 1:1，但避免全真或全假。
- 题干使用**可独立判定真假的陈述句**，不含选择题选项、不写“以下说法正确吗？”；通常 20–60 字，复杂内容可更长。保证不依赖看不到的原题。
- 错题须有**一个明确且真实存在的误区**；避免通过随意加“全部、绝不、完全”等词硬造明显错误（除非该绝对化本身就是重要易错点）。
- 对题干中的概念、因果、分类依据、程度词逐项核对。**正确题的整句话必须成立；错误题必须指出明确错误位置并给出正确表达。**
- 拒绝仅交换“正确 / 错误”或原句换几个同义词形成的机械重复。
- 跨教材存在不同分类或定义时，限定出处 / 语境，或不出存在歧义的题。

### 3. 写针对性解析与拓展

每题完整组织如下：

1. **明确考点**：每题给出简洁且可独立理解的知识点名称（如“教育影响的构成”“显性功能与隐性功能”），不是泛泛的“教育学基础”“第一章”；区分考点（在考什么）与记忆点（怎么记、如何判）。
2. **直接判定**：先指出正误核心，不重复一长串题干。
3. **关键依据**：解释关键概念、划分标准、必要条件；若为错误题，明确“错在 X，应为 Y”。
4. **对比 / 迁移**：补一个相邻易混点，或一个用于迁移判断的小情境；优先针对用户可能模糊的地方，不堆百科材料。
5. **记忆点**：用一句“区分口诀 / 触发词 / 对照关系”，通常 15–45 字；应有区分力，不能只重复题干。

使用 `**关键词**` 标记 1–3 处重点，便于网站高亮；不要直接输出 `<span>` 标签。保持观点谨慎：用户原文提供的是**材料依据**；根据通行知识补充的内容应当与材料保持区分，不捏造法规条文、理论出处或年份。若用户要求查证，引用可核实来源。

### 4. 输出简要易错点诊断

默认先给一段**易错点速览**，用 2–5 条简短条目概括：

- `核心：……；易混：……；判题抓手：……`
- 用户缺少原题时，不声称这是“原题考法”；表述为“依据解析推定的考查点”。
- 不做冗长全文改写，重点服务“我为什么会混淆、以后怎样区分”。

然后输出**一段可完整复制**的入库内容代码块。速览放在代码块外，避免被网站误解析成题目。

## 输出格式 A：直接粘贴到 edu-quiz（默认）

**必须为每道题输出五个独立字段**，顺序保持如下（所有字段都在独立行开头，以便网站识别）：

1. `【考点】`：精确说明本题考核的知识点，优先 4–18 字，不是宽泛学科名；即使同一原材料生成多题，也分别确定每题的考点侧重。
2. `【题干】`：可独立判断真假的陈述句，不写选择题字母。
3. `【解析】`：直接解释判定依据、错误位置、概念对照与必要拓展；**不得包含**单独的“考点/记忆点/判定”尾行。
4. `【记忆点】`：用于区分概念的简短口诀、边界或判断抓手，和解析分开。
5. `【判定】`：只能填写 `正确` 或 `错误`，与新生成题干对应，不能根据原选择题 A/B/C/D 推断。

要求：**题与题之间恰好一个空行、题内不留空行**；整组题放在一个纯文本代码块中，无编号或额外小标题。允许解析在后续非空行继续，但不要在正文内另用 `【考点】` 等标签。

示例（示范结构而非每题套用内容）：

```text
【考点】教育影响的构成
【题干】教育影响既包括教育内容，也包括教育手段。
【解析】该说法正确。**教育影响**连接教育者与受教育者，既包含“教什么”的内容，也包含“怎么教”的手段。
【记忆点】教育影响＝教育内容＋教育手段；内容看“教什么”，手段看“怎么教”。
【判定】正确

【考点】教育活动基本要素
【题干】教育活动的三个基本要素是教育者、受教育者和教育手段。
【解析】该说法错误。第三要素应是**教育影响**，教育手段只是教育影响的一个部分，不能以部分代替整体。
【记忆点】三要素：教育者、受教育者、教育影响；“手段”不是第三要素。
【判定】错误
```

网站已支持 `记忆点：`、`判定：` 的旧文本格式，但**新生成内容一律使用上述五个 `【】` 标签**，便于审核与后续修改。

如果来源不足以确定某题，宁可不生成该题；**不得把不确定的考点/判定伪装成已核实**。生成后提醒用户在预览中检查五个字段，尤其是判定和对考点的分类。

## 输出格式 B：JSON 章节包（用户明确要求或批量入库）

这个格式更稳妥，避免默认文本导入依赖答案推断；还会保留独立记忆点：

```json
{
  "chapters": [
    {
      "name": "教育学 · 第一章",
      "icon": "📘",
      "qs": [
        {
          "s": "<题干>",
          "a": false,
          "x": "<解析，用**关键词**突出重点，不含'判定：错误'>",
          "k": "<独立记忆点>",
          "g": "<本题精确考点>"
        }
      ]
    }
  ]
}
```

- 字段精确为 `chapters[].name`、`icon`、`qs[].s`、`qs[].a`（JSON 布尔值，**不是**字符串）、`qs[].x`、`qs[].k`、`qs[].g`。其中 `g` 为考点，`k` 为记忆点，二者不得合并到 `x`。可选 `v:2`。
- 一道题对应一个 `qs`，不要制造假 ID、假作答历史；该网站导入会自行分配题目 ID。
- 必须合法 JSON（使用双引号、转义换行与双引号；无末尾逗号），不要将 Markdown 代码围栏写进 `.json` 文件。
- 当可写文件时，生成 `edu_quiz_章节包.json` 并给出路径；不能写文件时仅输出 JSON 代码块，提示用户保存为 UTF-8 `.json`。
- **导入路径**：网站「更多 → 数据迁移 → 导入章节包 / 备份」；这是**追加新章节**，不是追加到既有同名章节，需提醒可能产生重复章节。
- 与格式 A 不同，`x` 不应含独立记忆点 `k` 或末尾判定标记，避免双重显示。

## 输出质量自检（不可省略）

发出内容前逐题核对：

1. 原文能否支撑答案？拓展是否被明确识别为拓展而非来源原话？
2. 不提供原题也能判定吗？是否没有用原单选题字母来决定正误？
3. 错题是否精准指出一个合理误区？正确题是否毫无偷换或条件遗漏？
4. 解析是否比“正确答案是……”多一步，能帮助区分相似概念？
5. 是否去重，题数是否合理，答案分布是否自然？
6. 格式 A：逐题依次有 `【考点】`、`【题干】`、`【解析】`、`【记忆点】`、`【判定】正确/错误`；题间一个空行，题内无空行；解析中不混入其他字段。
7. 格式 B：每题 `s/a/x/k/g` 完整；`a` 为真正布尔值；`g` 是考点而 `k` 是记忆点；JSON 可解析；导入会新增章节。

如果没有可靠依据生成某一题，宁可减少题数，并在代码块外指出需要补充的教材语境；不要编造概念与答案。

## 随包文件

- `README.md`：在 Codex / 普通 ChatGPT 中如何使用，以及网站操作。
- `examples/raw-analysis.txt`：只有解析，没有原题的示例输入。
- `examples/site-paste.txt`：可直接测试网站五字段导入的文本结果。
- `examples/chapter-import.json`：可直接测试网站导入的 JSON 章节包。
- `scripts/check_quiz.py`：离线检查生成文本/JSON 是否符合格式要求。
